# Настройка оплаты: ЮKassa, Telegram Stars, баланс, ручное подтверждение

Список активных способов задаётся в `.env`:

```env
PAYMENT_METHODS=yookassa,stars,balance,manual
```

Уберите лишние — кнопки исчезнут из бота. Если ЮKassa включена, но ключи не заполнены,
бот сообщит об этом при старте и не запустится (защита от «молчаливых» ошибок).

---

## 1. ЮKassa — карты РФ, СБП, SberPay

### Шаг 1. Получите доступы

1. Зарегистрируйте магазин на [yookassa.ru](https://yookassa.ru) (можно тестовый).
2. Личный кабинет → **Интеграция → Ключи API**: скопируйте `shopId` и **секретный ключ**.
3. Впишите их в `.env`:

```env
YOOKASSA_SHOP_ID=123456
YOOKASSA_SECRET_KEY=live_xxxxxxxxxxxxxxxxxxxx
YOOKASSA_RETURN_URL=https://t.me/your_bot_username   # куда вернуть пользователя после оплаты
```

Тестовые ключи (`test_...`) работают с `YOOKASSA_TEST=true` — удобно проверить поток без реальных денег.

### Шаг 2. Выберите способ подтверждения оплат

**Вариант А. Без домена (проще).** Ничего дополнительно настраивать не нужно:
бот сам опрашивает статус платежей каждые 3 минуты, плюс пользователь может нажать
«🔄 Проверить оплату» в карточке заказа. Оплата зачисляется в течение пары минут.

**Вариант Б. Вебхуки (мгновенно, рекомендуется при наличии домена).**

1. В `.env`:

```env
WEBHOOK_ENABLED=true
WEBHOOK_PORT=8080
WEBHOOK_PATH=/yookassa/webhook
WEBHOOK_PUBLIC_URL=https://bot.example.com/yookassa/webhook
```

2. Проксируйте адрес на локальный порт бота. Пример для nginx:

```nginx
server {
    listen 443 ssl;
    server_name bot.example.com;

    ssl_certificate     /etc/letsencrypt/live/bot.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/bot.example.com/privkey.pem;

    location /yookassa/webhook {
        proxy_pass http://127.0.0.1:8080/yookassa/webhook;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

3. В кабинете ЮKassa: **Интеграция → HTTP-уведомления** → добавьте событие `payment.succeeded`
   с адресом `https://bot.example.com/yookassa/webhook`.
4. Перезапустите бота: `systemctl restart dfvpnbot`. Проверить, что порт слушается:
   `curl -s http://127.0.0.1:8080/healthz`.

### Как бот защищается от подделки уведомлений

Телу вебхука не доверяем: получив `payment.succeeded`, бот **переспрашивает платёж**
через `GET /v3/payments/{id}` и проверяет, что:
- статус `succeeded` и `paid=true`;
- сумма совпадает с суммой заказа (±1 копейка).

Только после этого выдаётся доступ. Если обработка не удалась, бот отвечает `500`,
и ЮKassa повторит уведомление. Есть и вспомогательная проверка IP по официальным
диапазонам ЮKassa (`app/webhook.py`).

### Возвраты

Возврат оформляется в кабинете ЮKassa. Отметьте заказ отменённым в админке
(💰 Заказы) или выдайте доступ вручную — бот не списывает подписку автоматически.

## 2. Telegram Stars (`stars`)

Ничего настраивать не нужно — Stars работают в любом боте.

- Цена пересчитывается по курсу `STARS_RATE` (сколько рублей стоит 1 ⭐️, по умолчанию 1.5):
  `звёзд = цена ÷ STARS_RATE`.
- Оплата подтверждается мгновенно (`pre_checkout_query` + `successful_payment`).
- Отмена/отклонение счёта обрабатывается автоматически, заказ остаётся в ожидании.

Чтобы отдать звёзды обратно, используйте возврат в BotFather/Telegram; в коде для этого
есть готовая функция `refund_stars()` (`app/services/payments.py`).

---

## 3. Баланс (`balance`)

- Пользователь пополняет баланс картой или звёздами (теми же способами оплаты),
  а потом оплачивает подписку в один тап со скидкой «без комиссии».
- Лимиты пополнения: `MIN_TOPUP` (по умолчанию 100 ₽) и `MAX_TOPUP` (50 000 ₽).
- Реферальные бонусы и ручные правки админа тоже падают на баланс — видно в профиле
  пользователя и в логе платежей.

---

## 4. Ручное подтверждение (`manual`)

Для переводов на карту, крипты и любых внешних способов:

1. В `.env` задайте текст-инструкцию:

```env
MANUAL_PAYMENT_NOTE=Переведите сумму на карту 0000 0000 0000 0000 и пришлите чек в поддержку.
```

2. Пользователь выбирает «🧾 Оплачу вручную» — заказ помечается как ожидающий, админам
   приходит уведомление.
3. Админ открывает `/admin` → 💰 Заказы → ✅ Подтвердить оплату — бот сразу выдаёт ключ
   и уведомляет клиента (либо ❌ Отклонить).

---

## Что происходит после успешной оплаты

1. Заказ получает статус `paid`, в лог платежей пишется сумма и способ.
2. Бот выдаёт ключ: создаёт клиента в панели (`xui`/`marzban`) или берёт из пула (`pool`).
3. Если у пользователя уже есть активная подписка на той же панели — срок продлевается,
   ключ не меняется.
4. Начисляется реферальный бонус пригласившему (`REF_PERCENT`).
5. Пользователь получает карточку подписки, QR-код и инструкцию; админы — уведомление.

Если выдача не удалась (например, пул пуст или панель недоступна), пользователь получает
честное сообщение «оплата получена, выдадим вручную», а админам уходит тревожный алерт —
деньги не теряются.
